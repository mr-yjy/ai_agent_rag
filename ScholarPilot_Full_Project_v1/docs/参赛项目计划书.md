# 研索智航 ScholarPilot 参赛项目计划书

## 一、项目概况

### 1. 项目名称

研索智航：面向复杂学术查询的预算感知多策略论文检索智能体。

### 2. 参赛方向

- 主报：华为企业赛题三——科研场景下复杂学术查询的智能论文搜索与推荐；
- 兼报：开放命题应用创意类——生成式大语言模型与智能体。

### 3. 项目背景

研究者在开题、文献综述和方向调研中，常常不是寻找某一篇论文，而是需要
在多个限制条件下得到一个相对完整且准确的论文集合。复杂查询可能同时
包含主题、方法、数据集、年份、发表源、实验和开源代码等条件。

传统关键词检索难以处理组合约束。通用大模型虽然能够生成论文推荐，
但容易遗漏相关工作、混淆约束或生成不存在的文献信息。因此需要将大模型
查询理解、学术搜索 API、分阶段排序、引文网络与证据核验结合起来。

## 二、建设目标

### 1. 总体目标

在比赛提交前完成可运行、可演示、可评测、可复现的学术论文智能搜索系统，
并证明其相对于直接关键词搜索在 F1 或成本—效果平衡上具有稳定提升。

### 2. 功能目标

- 复杂查询理解；
- Query Contract；
- 多查询路线规划；
- OpenAlex 和 Semantic Scholar；
- 关键词和语义召回；
- 级联精排；
- 引文网络扩展；
- 证据核验；
- 预算控制；
- 结构化论文列表和关系展示；
- 搜索轨迹与成本统计。

### 3. 指标目标

内部目标，不代表赛题官方阈值：

- F1@20 相对直接搜索 Baseline 稳定提升；
- 单次查询 API 调用和 Token 可配置；
- 90%以上开发集查询能返回有效结构化结果；
- 实时 Provider 失败时系统可降级；
- 同一配置和缓存下实验可复现；
- 5分钟内完整展示核心工作流和实验结果。

## 三、技术路线

### 1. Baseline

```text
原查询 → OpenAlex → 透明排序 → Top-K
```

### 2. 正式方案

```text
复杂问题
  → Query Contract
  → 关键词、语义、方法×任务子查询
  → OpenAlex + Semantic Scholar
  → DOI/ID/标题去重
  → BM25 + Embedding
  → Cross-Encoder
  → 引文扩展
  → 反事实证据核验
  → 预算停止
  → 结构化结果
```

### 3. 主要创新点

#### 创新点一：约束驱动的查询规划

不是简单改写整句话，而是显式区分 must、preferred 和 exclude，使召回和
排序能够针对不同条件分别优化。

#### 创新点二：多路线召回与来源追踪

记录每篇论文由关键词、语义还是引文路线找到，从而分析每条路线对 Recall
的真实贡献。

#### 创新点三：反事实约束核验

改变一个关键条件，如果候选论文的判断几乎不变，说明模型可能没有真正
依据约束判断，应降低置信度。

#### 创新点四：预算感知停止

根据新增高相关论文数量、Top-K稳定度和剩余预算决定是否继续搜索，而不是
固定搜索轮数。

## 七、风险与应对

| 风险 | 可能后果 | 应对 |
| --- | --- | --- |
| API限流 | Demo失败 | 缓存、第二数据源、演示降级 |
| 无标注集 | 无法证明提升 | 第一优先级建立benchmark |
| 功能堆叠 | 无法解释贡献 | 模块开关和消融 |
| LLM成本高 | 效率失分 | 级联排序、边界样本调用 |
| 引文噪声 | Precision下降 | 高置信种子和扩展上限 |
| CS领域过拟合 | 泛化性失分 | 五领域分层评测 |
| 时间不足 | 材料不完整 | M0/M1优先，功能按指标进入 |
| 论文信息幻觉 | 可信度下降 | 只输出Provider真实元数据 |
| 密钥泄漏 | 安全问题 | 环境变量和提交前扫描 |

## 十、阶段决策原则

一个新模块只有满足以下条件才进入最终作品：

1. 在固定验证集上有可重复提升，或者明显降低成本；
2. 有关闭开关；
3. 有消融结果；
4. 有失败案例分析；
5. 能在答辩中用流程和公式解释；
6. 不依赖无法在评审环境复现的私有服务。
