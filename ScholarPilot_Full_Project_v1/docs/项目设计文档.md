# 研索智航 ScholarPilot 项目设计文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 项目名称 | 研索智航 ScholarPilot |
| 目标赛题 | 科研场景下复杂学术查询的智能论文搜索与推荐 |
| 文档版本 | 1.0 |
| 当前阶段 | 可运行 MVP |
| 核心语言 | Python、TypeScript |
| 当前数据源 | OpenAlex、内置演示数据 |

## 2. 项目目标

ScholarPilot 面向普通关键词搜索难以处理的复杂科研问题，将自然语言需求
转换为结构化约束和多个互补子查询，检索论文后完成去重、排序、证据提取
和成本统计。

系统不直接追求生成一段看似完整的答案，而是优先返回一个：

- 可追溯；
- 可验证；
- 可复现；
- 可继续扩展；
- 能够计算 Precision、Recall 和 F1

的相关论文集合。

## 3. 典型输入

```text
寻找 2024—2026 年使用查询分解或引文扩展进行复杂学术论文检索的
LLM Agent 论文，优先包含公开代码和完整实验，排除纯综述。
```

系统应识别：

| 类型 | 识别结果 |
| --- | --- |
| 时间 | 2024—2026 |
| 任务 | academic paper search |
| 方法 | query decomposition、citation expansion |
| 系统 | LLM Agent |
| 偏好 | open source、evaluation |
| 排除 | 纯综述 |

## 7. Python 后端模块设计

### 7.1 models.py

职责：

- 定义 QueryPlan、Paper、RankedPaper、SearchStats；
- 统一内部 Python 命名；
- 输出与网页兼容的 camelCase JSON。

不得包含：

- 网络请求；
- 排序算法；
- 业务流程。

### 7.2 planner.py

职责：

- 规范化中英文查询；
- 识别年份；
- 识别必须满足方法；
- 识别偏好和排除；
- 生成互补子查询；
- 提供排序共用 Tokenizer。

当前为规则 Baseline。后续 LLM Planner 必须作为可开关模块加入，不能删除
规则版本，因为规则版本是消融实验基线和故障回退。

### 7.3 providers.py

统一接口：

```python
class PaperProvider(Protocol):
    name: str
    def search(self, plan: QueryPlan) -> ProviderResult: ...
```

实现：

- DemoProvider：读取本地 JSON；
- OpenAlexProvider：实时请求、映射、缓存、去重；
- 后续 SemanticScholarProvider。

### 7.4 ranking.py

当前打分：

```text
Score =
  0.55 × Relevance
  + 0.20 × Constraints
  + 0.10 × Authority
  + 0.10 × Recency
  + 0.05 × Openness
```

其中：

- Relevance：查询 Token 与标题、摘要、概念的重叠；
- Constraints：方法覆盖和年份满足；
- Authority：被引次数对数归一化；
- Recency：发表年份归一化；
- Openness：是否开放获取。

选取 Top-K 时使用冗余惩罚，避免十篇结果标题和摘要几乎相同。

这些权重只是 Baseline，必须在验证集上调优。

### 7.5 service.py

完整业务入口：

1. 查询长度检查；
2. 构建 QueryPlan；
3. 选择 Demo 或 Live Provider；
4. 实时失败时降级；
5. 排序；
6. 统计耗时、候选、API、Token；
7. 输出统一 JSON。

### 7.6 server.py

零依赖 HTTP 服务：

- ThreadingHTTPServer；
- JSON 请求和响应；
- CORS；
- 1MB 请求上限；
- 健康检查；
- 搜索接口；
- 400、404、500 状态码。

### 7.7 fastapi_app.py

FastAPI 只负责：

- 输入模型；
- OpenAPI/Swagger；
- HTTP 错误转换；
- CORS；
- 调用 SearchService。

算法不能写在 FastAPI 路由中。

## 8. API 设计

### 8.1 GET /api/health

响应：

```json
{
  "ok": true,
  "service": "scholarpilot-python",
  "version": "0.2.0"
}
```

### 8.2 POST /api/search

请求：

```json
{
  "query": "复杂科研问题",
  "mode": "demo",
  "limit": 10
}
```

约束：

- query：6—800字符；
- mode：demo/live；
- limit：1—50。

响应主要结构：

```json
{
  "mode": "demo",
  "provider": "内置比赛演示数据",
  "warning": "可选",
  "plan": {},
  "results": [],
  "stats": {}
}
```

## 9. 数据流

```text
HTTP JSON
  → 输入校验
  → QueryPlan
  → Subqueries
  → Provider Responses
  → Paper 统一结构
  → 去重
  → 五维打分
  → MMR 选取
  → Evidence
  → RankedPaper JSON
```

## 10. 异常与降级

| 异常 | 当前处理 |
| --- | --- |
| 查询过短 | 400 |
| 查询过长 | 400 |
| JSON 错误 | 400 |
| 路径错误 | 404 |
| OpenAlex 超时 | 自动使用演示数据并返回 warning |
| OpenAlex 空结果 | 自动使用演示数据 |
| 未知服务器错误 | 500，不返回内部堆栈 |

比赛版需要增加：

- 结构化日志；
- request_id；
- 重试和指数退避；
- 熔断；
- Provider 级超时；
- 实验轨迹持久化。

## 11. 配置和密钥

```text

```

- `.env` 不提交；
- `.env.example` 只保留变量名；
- 日志不得打印 Key；
- 比赛代码提交前执行密钥扫描。

## 15. 验收标准

当前 MVP 验收：

- 无第三方依赖可启动；
- 健康检查返回200；
-搜索接口返回结构化结果；
- 自定义查询改变 QueryPlan 和排序；
- 实时接口失败不导致 Demo 中断；
- 排序包含评分和证据；
- 自动测试全部通过；
- 源码、设计文档和计划书可下载。
