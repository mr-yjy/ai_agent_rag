## P0：未来 7 天必须完成

### 1. 建立小型验证集

先标注 30 条查询，而不是一开始做 100 条。

每条记录至少包含：

```json
{
  "query_id": "q001",
  "query": "复杂科研问题",
  "relevant_paper_ids": ["doi or OpenAlex id"],
  "domain": "computer_science",
  "notes": "标注依据"
}
```

验收：

- 30 条查询；
- 至少覆盖 3 个学科；
- 每条至少有一个相关论文；
- 标注规范写成单独文档。

### 2. 实现评测脚本

输入：

- 查询集；
- 系统输出 Top-K；
- 标准相关论文集合。

输出：

- Precision@10；
- Recall@20；
- F1@20；
- 平均 API 调用；
- 平均延迟；
- 每个领域的分项指标。

### 3. 保存搜索日志

每次实验保存：

- 原查询；
- Query Contract；
- 子查询；
- 原始候选；
- 去重结果；
- 各阶段分数；
- 最终排序；
- API、Token 和延迟；
- 错误和降级信息。

## P1：第 2 周

### 4. Embedding 语义召回

建议先使用一个成熟的多语言 Embedding 模型，不做微调。

实验：

- 仅关键词；
- 仅 Embedding；
- 关键词 + Embedding 融合。

必须报告 Precision、Recall、F1 和延迟，不能只展示个别案例。

### 5. Cross-Encoder 精排

只对粗排 Top-50 执行。

实验：

- Top-20、Top-50、Top-100 三种输入规模；
- 比较 F1 与延迟；
- 收集 False Positive 作为难负样本。

### 6. 把透明权重移入配置

当前权重写在代码中。应改为配置文件并支持：

- 命令行覆盖；
- 实验名称；
- 配置哈希；
- 批量网格搜索；
- 最佳配置导出。

## P2：第 3 周

### 7. 引文网络扩展

规则：

- 只扩展 Top-5 高置信论文；
- 每篇最多取固定数量参考文献和被引论文；
- 最多两轮；
- 记录每篇候选由哪条路径找到。

对比：

- 无引文扩展；
- 一轮；
- 两轮。

### 8. 预算停止

第一版先用可解释规则：

```text
连续两轮新增高相关论文 < 2
或 Top-20 排名稳定度 > 0.95
或达到 API/Token/时间预算
则停止
```

与固定 1、2、3 轮搜索比较。

### 9. 反事实核验

只对 Top-20 中分数位于阈值附近的论文调用。

输出必须包含：

- 原约束判断；
- 摘要证据；
- 反事实约束；
- 分数变化；
- 最终保留或降权原因。

## 推荐的后续 Codex 指令

### 任务 1：评测集

> 在当前 ScholarPilot 项目中新增 benchmark 目录，定义 JSONL 数据格式、
> 标注指南和 30 条查询的空白模板。不要修改检索算法。

### 任务 2：评测脚本

> 为 ScholarPilot 实现可复现的离线评测，输出 P@10、R@20、F1@20、
> 平均 API 调用和平均延迟，并为指标函数增加单元测试。

### 任务 3：Embedding

> 在保留当前透明排序作为 baseline 的前提下，增加可开关的多语言
> Embedding 召回。先写实验配置和对比测试，不要删除 baseline。

### 任务 4：Cross-Encoder

> 增加只处理粗排 Top-50 的 Cross-Encoder 精排模块。所有模型名称、
> batch size、设备和权重必须进入配置，并输出延迟和消融结果。

### 任务 5：引文扩展

> 为 OpenAlex provider 增加一轮可控引文扩展，保存候选来源路径，
> 限制种子数和扩展数量，并比较启用前后的 Recall@20 和 API 成本。

### 任务 6：反事实核验

> 实现只针对边界候选的反事实约束核验，要求输出摘要证据和降权原因，
> 并增加 Token 预算上限和关闭开关。

## 明确禁止

- 没有验证集就宣称 F1 提升；
- 用生成式模型编造 DOI、作者或论文标题；
- 把 OpenAlex 返回条数当成 Recall；
- 同时更换召回、排序和 Prompt 后只报告最终结果；
- 为了界面好看隐藏 API 失败和降级；
- 把尚未实现的模块写成“系统已完成”；
- 在代码中提交 API Key；
- 最后一天才录视频或上传材料。
